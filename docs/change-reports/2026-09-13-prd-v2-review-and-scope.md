# 知识拼桌核心 PRD V2 评审与收敛方案

评审日期：2026-09-13

## 1. 总体结论

PRD 的产品方向成立，但目前混合了产品愿景、用户流程和实现约束。建议保留“听 → 选 → 碰 → 校 → 请 → 留”的主叙事，同时压缩主路径，把举手追问、继续互质、主持人梳理降级为可选支线。

推荐主路径：

    听两席
      ↓
    记录倾向
      ↓
    选择碰撞点
      ↓
    完成一次质疑—回应
      ↓
    校准隐藏分歧
      ↓
    生成并选择第三视角
      ↓
    留下思考变化

## 2. 应保留的核心内容

### 2.1 产品定位

知识拼桌不应是多篇回答并排展示，也不应是多个 Agent 各说各话。核心价值是让不同知识立场围绕用户选中的具体问题发生一次结构化碰撞，并留下用户思考变化的过程。

### 2.2 三层知识结构

保留第一席、第二席和第三视角：

- 第一席：一个明确立场；
- 第二席：另一个有差异的立场；
- 第三席：从用户确认的隐藏分歧中产生的新判断框架。

第三席不是预先固定的第三个答主，而是本次讨论生成的条件化视角。

### 2.3 用户发起碰撞

保留规则：

> 用户选中哪一席的论点，就由另一席先质疑，原发言席再回应。

这是产品最有辨识度的互动规则，能够避免系统自说自话。

### 2.4 用户校准隐藏分歧

保留以下机制：

- AI 提出 2—3 个候选；
- 用户可以选择、组合、修改或否定；
- 用户拥有对自身问题的最终解释权。

### 2.5 记录思考变化

最终结果应保留：

- 讨论前倾向；
- 碰撞中关注的风险；
- 讨论后的变化；
- 仍未解决的问题；
- 用户自己的一句话。

结果不应退化为“建议辞职”或“不建议辞职”。

## 3. 应修改的内容

### 3.1 明确两席发言的生成方式

PRD 需要明确每席内容不是简单截取原文，而是：

    检索相关来源
      ↓
    按席位 Prompt 组织观点
      ↓
    展示观点、边界和来源

如果暂时没有聊天模型，也要明确标注为“来源摘录”，不能称为“AI 生成”。

### 3.2 把检索和生成拆开

PRD 中的“AI 生成”应拆成三种能力：

| 能力 | 作用 |
|---|---|
| 检索 | 找到当前话题、席位和问题相关的来源 |
| 生成 | 根据用户问题、席位立场和来源重新组织回答 |
| 校验 | 防止跨席位、编造和来源越界 |

尤其是举手追问，必须定义为“检索 + 生成”，不能只是检索后直接摘录。

### 3.3 统一席位命名

产品界面可使用：

- 第一席·行动派；
- 第二席·现实派；
- 第三席·条件视角。

数据层继续使用稳定 ID：

- action；
- realist；
- conditional。

### 3.4 增加第一席和第二席的独立阶段

当前实现从 intro 直接进入 tendency，前两席没有真正的依次发言阶段。应改为：

    home → intro → first-seat → second-seat → tendency

用户可以在每席发言后追问，完成后回到原席位，再继续下一席。

### 3.5 收敛用户输入入口

将多个入口收敛为：

1. 举手追问：针对某一席的自由问题；
2. 补充条件：在碰撞阶段补充个人情况。

“继续互质”和“请主持人梳理”先作为后续版本能力，不要同时作为首版独立入口。

## 4. 建议去除或后置的内容

### 4.1 去除“第四席：用户”

用户不是观点席位，建议改为独立角色“用户”。用户负责选择、提问、发起碰撞、校准和表达。

### 4.2 后置 AI 推荐碰撞点

当前实现中的碰撞点主要来自固定论点配置，还没有真正分析两席发言后推荐矛盾点。V2 首版只保留：

- 选择已有论点；
- 输入自己的问题。

AI 自动推荐碰撞点放入后续版本。

### 4.3 无限互质降级为可选

一次质疑—回应已经足够提取隐藏分歧。继续互质最多作为一个“再碰一轮”按钮，不应成为主路径，也不应无限开放。

### 4.4 离桌选择不应强制

保留快速选项和自由表达，但允许用户跳过，直接查看讨论地图。

### 4.5 暂时不要承诺每个视角都有知乎来源

第三视角只有在生成链路和来源绑定稳定后，才承诺来源。此前应写成“尽可能提供可追溯参考来源”。

## 5. 推荐的完整流程

### A. 进入话题

展示话题标题、体验说明、预计时长和加入拼桌按钮。

### B. 第一席发言

展示核心观点、理由、边界、2—3 个碰撞论点、参考来源和举手追问入口。

追问结束后显示回归锚点，例如：

> 刚才行动派正在讨论“持续失眠是否足以支持裸辞”。要继续听下一派吗？

### C. 第二席发言

展示与第一席相同的内容结构。追问结束后进入倾向记录。

### D. 记录首次倾向

提供五个选项：

- 更接近第一席；
- 更接近第二席；
- 两边都有道理；
- 暂时无法判断；
- 两边都没说到重点。

可以额外选择最影响自己的一句话。

### E. 选择碰撞点

碰撞点来自已有论点或用户自己输入的问题。首版不强依赖 AI 推荐。

### F. 一次质疑—回应

固定顺序：

1. 用户选中原发言席；
2. 另一席提出质疑；
3. 原发言席回应；
4. 主持人指出可能的真正分歧。

允许用户补充一次个人情况。

### G. 校准隐藏分歧

AI 提供 2—3 个候选，用户可以选择、组合、改写或选择“都不是”。

### H. 第三视角预览

展示名称、生成依据、问题重构、判断工具、参考来源和限制说明。

### I. 邀请或跳过

保留：

- 邀请入桌；
- 换一个视角；
- 让前两席继续回应；
- 不邀请，直接整理。

继续回应默认只增加一次简短回应。

### J. 离桌结果

展示共识、真正分歧、隐藏前提、未解决问题、思考轨迹、用户的一句话和参考来源。

## 6. 当前项目与 PRD 的差距

### 已具备

- 话题大厅；
- action、realist、conditional 三席数据；
- 碰撞点选择；
- 一次质疑—回应；
- 隐藏分歧候选；
- 第三视角预览；
- 邀请第三席；
- 最终讨论地图；
- 举手追问入口；
- 本地 RAG 数据和来源链接；
- API 缺失时的 fallback。

### 尚未真正实现

- 第一席到第二席的独立发言状态；
- 每席完整的动态观点生成；
- 追问的聊天模型生成；
- AI 动态推荐碰撞点；
- 用户补充条件进入后续回答；
- 稳定的多轮互质；
- 第三视角稳定的来源追溯；
- 自由离桌表达与结果融合；
- 追问请求并发保护；
- 返回前的席位来源校验。

### 主要不一致

当前状态大致是：

    home → intro → tendency → collision-point → collision-response
          → divergence → perspective-preview → result

PRD 需要：

    home → first-seat → second-seat → tendency → collision-point
          → collision-response → divergence → perspective-preview
          → third-seat 或 result

当前 discuss、followup 和 summary 大量采用“检索 top[0] 后截取原文”的方式，这与 PRD 中的情境化回应不一致。

## 7. 推荐状态机

主流程：

    home
      ↓
    intro
      ↓
    first-seat
      ↓
    second-seat
      ↓
    tendency
      ↓
    collision-point
      ↓
    collision-response
      ↓
    divergence
      ↓
    perspective-preview
      ↓
    third-seat 或 result
      ↓
    result

举手追问不作为主 stage，而作为 first-seat 或 second-seat 下的可叠加支线，结束后回到原 stage。

## 8. V2 取舍表

| 需求 | V2 处理 | 原因 |
|---|---|---|
| 两席依次发言 | 必须保留 | 产品核心叙事 |
| 每席碰撞点 | 必须保留 | 支撑用户发起碰撞 |
| 举手追问 | 保留为支线 | 增加个性化但不阻塞主流程 |
| 一次质疑—回应 | 必须保留 | 核心差异化 |
| 无限互质 | 降级为可选 | 防止流程过长 |
| 补充个人情况 | 保留一次 | 提升个性化 |
| AI 推荐碰撞点 | 后置 | 当前能力不足 |
| 隐藏分歧候选 | 必须保留 | 产品核心价值 |
| 用户校准 | 必须保留 | 保留用户解释权 |
| 第三知识视角 | 必须保留 | 形成独特产出 |
| 自由离桌表达 | 保留但可跳过 | 不应阻塞结果 |
| 每个回答都带来源 | 改为尽可能提供 | 避免无法兑现 |
| 原文直接截断 | 去除为默认行为 | 容易断句和答非所问 |
| 多赛季和 20 房间 RAG | 作为外围功能 | 不干扰核心流程 |

## 9. 必须增加、保留和删除

### 必须增加

1. 第一席和第二席独立发言阶段；
2. 追问的聊天模型生成；
3. 席位和来源校验；
4. 用户补充情况进入后续流程；
5. 第三视角的生成依据和来源；
6. 可跳过的离桌自由表达；
7. 检索、生成和 fallback 的准确模式标识。

### 必须保留

1. 听 → 选 → 碰 → 校 → 请 → 留；
2. 用户发起碰撞；
3. 一次质疑—回应；
4. 用户确认隐藏分歧；
5. 第三知识视角；
6. 思考轨迹；
7. 来源可追溯。

### 建议删除或后置

1. “用户是第四席”的称谓；
2. 无限互质；
3. 首版强制 AI 推荐碰撞点；
4. 所有回答直接摘录原文；
5. 强制离桌选择；
6. 尚未稳定时承诺每个视角都有来源；
7. 把 embedding 检索标记为 AI 生成。

## 10. 收敛后的产品定义

> 知识拼桌让用户先听懂两个有来源的观点，再亲自挑起一次具体碰撞，确认真正的分歧，最后带走一个由这次讨论生成的判断框架，而不是一个替用户做决定的答案。
