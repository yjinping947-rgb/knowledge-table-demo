# 知识拼桌最终页 PRD：讨论余波地图与灵魂金句

版本：V2.1

## 1. 产品目标

最终页不再展示传统思维导图或四张等权重总结卡，而是让用户一眼看到：中心问题、三个讨论发现、自己的立场变化，以及最后带走的一句话。

核心表达：问题在中心，讨论发现围绕它留下余波，用户立场用轨迹表达，底部留下一句灵魂金句。

## 2. 固定视觉规范

- 中心问题：1 个，建议 8—16 字，最多两行。
- 外围结论：最多 3 个，每个 4—6 字，只用短语，不写完整句子。
- 用户轨迹：1 条，只表达“起点 → 碰撞 → 当前”，不写解释段落。
- 灵魂金句：1 条，建议 18—32 字，最多 40 字。
- 来源：放入底部折叠区，不堆在地图主体中。

## 3. 地图构图

地图采用“中心问题 + 外围结论 + 立场轨迹”的结构：

    讨论余波

      结论 A       结论 B
             中心问题
                结论 C

          用户立场轨迹

外围结论不是中心问题的子节点，而是讨论产生的三道余波：

1. 核心冲突；
2. 隐藏前提；
3. 第三知识视角。

## 4. 三个外围结论

### 核心冲突

来源于用户选中的碰撞点、另一席的质疑和原席回应。

示例：健康 × 现金

### 隐藏前提

来源于用户确认的隐藏分歧和双方默认前提的差异。

示例：还能撑吗？

### 第三知识视角

来源于第三席名称、问题重构和判断工具。

示例：求职能力

生成时删除“问题在于”“我们需要考虑”等虚词，只保留冲突对象、判断动作或关键条件，并严格限制在 4—6 字。

## 5. 用户轨迹

轨迹只显示视觉节点，不显示长解释：

- 起点：用户讨论前的倾向；
- 碰撞：用户选择并推动的具体论点；
- 当前：讨论后的行动派、现实派、条件视角或未确定。

允许的路径包括：

    行动派 → 碰撞 → 行动派
    行动派 → 碰撞 → 现实派
    行动派 → 碰撞 → 条件视角
    行动派 → 碰撞 → 未确定

轨迹颜色使用深灰，终点可使用强调色；颜色不能单独承担语义，必须同时显示文字标签。

## 6. 灵魂金句

灵魂金句不是四象限字段拼接，也不是直接复制 RAG 原文，而是回答：这一桌讨论结束后，用户真正带走了什么判断？

生成输入最多包括：中心问题、初始倾向、碰撞点、隐藏分歧、第三视角和用户最终表达。

生成规则：

- 18—32 字为宜，最多 40 字；
- 不直接复述中心问题；
- 不使用“AI 认为”“本次讨论表明”等系统口吻；
- 不强行给出“应该辞职 / 不应该辞职”的结论；
- 表达一个新的判断框架或下一步观察线；
- 尽量使用用户语言。

示例：

- 你不是在选辞不辞，而是在选哪种代价更能承受。
- 先确认缓冲是否真实存在，再决定要不要离开。
- 真正的安全，不是一直留下，而是还保留调整的空间。

## 7. 最终页结构

### 顶部

保留“分享”和“提供反馈”，但不与地图争夺视觉中心。

### 地图主体

1. 小标题：讨论余波；
2. 中央问题；
3. 三个外围结论；
4. 用户立场轨迹；
5. 极简图例（可选）。

### 金句区域

地图下方用分隔线隔开：

    带走一句
    你不是在选辞不辞，而是在选哪种代价更能承受。

### 来源区域

使用“查看本桌参考来源”折叠区，展开后显示观点席、碰撞点和第三视角来源。

## 8. 数据结构

    type DiscussionMap = {
      question: string;
      ripples: Array<{
        label: string;
        type: "conflict" | "premise" | "perspective";
        sourceSeat?: "action" | "realist" | "conditional";
      }>;
      trajectory: {
        start: "action" | "realist" | "undecided";
        checkpoints: Array<"action" | "realist" | "conditional" | "collision">;
        end: "action" | "realist" | "conditional" | "undecided";
      };
      soulSentence: string;
    };

约束：`ripples` 最多 3 项；每个 `label` 4—6 字；`soulSentence` 最多 40 字。

## 9. 与当前 ResultStage 的关系

保留并重新表现：

- `trajectory` 改为视觉轨迹；
- `consensus`、`disagreement`、`hiddenAssumption` 压缩为三个外围结论；
- `perspective` 压缩为第三知识视角；
- `openQuestion` 可作为详情或金句生成输入。

不再作为地图主体展示：

- 四张等权重 MapCard；
- 长段落 thoughtTrail；
- 完整质疑与回应；
- 作者、来源和说明文字堆叠。

点击外围结论时，可展开原始长文本、质疑与回应、对应来源和用户确认内容。

## 10. 验收标准

### 视觉

- 一眼看出中心问题；
- 外围不超过三个结论；
- 地图没有长段落；
- 轨迹明显但不抢中心问题；
- 金句是页面第二视觉焦点；
- 移动端无重叠和横向溢出。

### 内容

- 三个结论都来自本次讨论；
- 每个结论 4—6 字；
- 轨迹反映用户状态变化；
- 金句不是四象限复述；
- 不强迫用户接受二选一结论。

### 真实性

- 来源可追溯；
- 不跨席位引用；
- 生成失败时仍展示结构完整的地图；
- 不把检索原文直接冒充灵魂金句。

## 11. V2.1 取舍结论

必须增加：`discussionMap`、三个短结论压缩、轨迹编码、`soulSentence` 校验、来源折叠区、分享和反馈入口。

必须保留：中心问题、三个外围结论、用户轨迹、灵魂金句、来源可追溯和用户不被强迫得出二选一结论。

建议去除：四张等权重结果卡作为默认主体、地图主体长篇 thoughtTrail、超过三个外围结论、用长文字解释轨迹、把 embedding 检索标记为 AI 生成。

## 12. 最终页一句话

> 一张中心问题的桌子，三道讨论余波，一条用户立场轨迹，最后留下一句真正带得走的话。
