## 背景

P0 的"知识拼桌"是单话题讨论 demo（围绕"年轻人该不该裸辞"）。P1 想扩展到"多个房间"：每个房间对应一条知乎问答，有一个"人设"（原答主），用户可以进房间问问题，RAG 检索该答主语料生成回答。

前置依赖：
- `3efeb6f feat(rag)`：本地 RAG 检索（28 条语料 + 28×1536 维 embedding）
- `488944d feat(data+llm)`：真实数据 + LLM 网关

## 变更前预期

### 用户行为

- 主页变成 20 个房间的网格
- 点击房间进入详情页（chat 形式）
- 在房间里问问题，RAG 检索该答主语料 + LLM 生成回答
- `roomId` 强制 top[0] 是该答主自己的语料（保证"人设"）

### 数据 / API

- `GET /api/answer`：列出所有房间
- `GET /api/answer?roomId=r01`：查单个房间
- `POST /api/answer { question, k?, roomId? }`：RAG 检索 + LLM 回答
- 新增 `src/data/rooms.json`：20 个房间配置（id / title / author / excerpt / sourceUrl / corpusId / voteUpCount / commentCount）

### 兼容性

- 不破坏原有 `/api/discuss` `/api/summary`
- `components/KnowledgeTable.tsx` 从 `src/client/knowledge-table` 改指 `src/client/rooms-app`
- 老 demo（2 轮讨论）仍然在 `src/client/knowledge-table/`，可通过直接 import 访问

### Harness 影响

- 新增 RAG pipeline（`src/lib/rag/`），不直接归属任何已有 agent（由 director 间接管）
- 主页从 2 轮讨论 demo 切换到 20 房间 demo — 算是"主入口变更"
- 新增 `app/api/answer/route.ts` — 不在原 2 个契约里，但格式与 `discuss/summary` 风格一致

## 变更后端测效果

### 自动化测试

- `npm run lint`：通过
- `npm run build`：通过
- `node tests/core-branches.mjs`：PASS（27 路径全绿，未受 rooms 影响）

### 手动验证

- 主页打开 → 看到 20 个房间网格（每个有标题、答主、点赞数、评论数）
- 点击 r01（25 岁 HR 答主）→ 进入 RoomDetail
- 输入 "我该听你的建议吗？" → RAG 检索 top 4 篇 → LLM 用 [25 岁 HR 答主] 风格回答 + 标注引用
- `GET /api/answer`：返回 `{ rooms: [20 rooms] }`
- `GET /api/answer?roomId=r02`：返回 r02 详情
- `POST /api/answer { question, k: 4 }`：返回 `{ answer, retrieved, mode }`
- `POST /api/answer { question, k: 4, roomId: "r02" }`：top[0] 是 Sakura 自己的语料

### 边界 / 异常

- 缺 `AI_API_KEY` → fallback 模式（用 corpus 拼接的"演示回答"）
- 房间 id 不存在 → 404
- question 缺失 → 400
- 缺 `roomId`：退化为不带人设的全局 RAG
