# 知识拼桌核心流程 PRD

版本：V2.5
状态：最终核心流程版
基于：V2.3-修订版，并吸收 V2.4.1 的碰撞交互、证据结构与验收规则
Demo 话题：年轻人该不该裸辞？
产品形态：移动端优先 Web Demo

---

## 1. 产品定义

知识拼桌把知乎社区中的真实经验和不同判断方式组织成一张可参与的圆桌。

它不是：

- 多篇回答并排展示；
- 多个 Agent 自由聊天；
- 让 AI 替用户做决定；
- 把检索到的原文直接截断后当成回答；
- 通过星标或点赞给观点排序。

它的核心体验是：

> 用户先听两个有来源、彼此不同的观点，选择一个具体问题让它们发生一次碰撞，从碰撞中确认真正的隐藏分歧，可选择邀请第三席提供新判断框架，最后带走一张“讨论地图 + 灵魂金句”的可分享卡片。

核心闭环：

    听两个观点
      → 选择当前倾向
      → 选择具体碰撞点
      → 将碰撞点递到两席之间
      → 一轮质疑—回应
      → 确认隐藏分歧
      → 可选：生成并邀请第三席
      → 记录当前理解
      → 生成讨论地图 + 灵魂金句分享卡

## 2. 产品目标与非目标

### 2.1 产品目标

1. 让用户在 3—5 分钟内听懂两个有依据、但判断不同的观点；
2. 让用户主动选择一次具体而真实的观点碰撞；
3. 让用户看见表面立场背后的风险、前提或时机差异；
4. 让用户获得新的判断框架，而不是被推向预设答案；
5. 将讨论过程压缩成一张清晰、可分享的结果卡片；
6. 保留每个结论的证据边界和来源可追溯性。

### 2.2 非目标

- 不提供医疗、法律、债务或财务上的确定性决策；
- 不模拟或冒充具体知乎答主本人；
- 不做思想家视角或名人方法论 Agent；
- 不做星标、点赞驱动的知识卡；
- 不做无限多轮自动辩论；
- 不建设账户、公开社区、积分、长期档案；
- 不把用户引导到“应该辞职”或“应该留下”的固定结论；
- 不要求第三席一定出现；
- 不要求用户必须形成确定答案。

## 3. 核心设计决策

| 决策 | V2.5 定义 |
|---|---|
| 初始观点 | 每桌先有第一席和第二席两个不同观点 |
| 第三席 | 由碰撞和用户确认的隐藏分歧生成，可邀请，也可跳过 |
| 思想家 | 不做，不进入主流程或可选支线 |
| 星标 | 不做，不作为内容选择、排序或总结依据 |
| 碰撞触发 | 选择碰撞点后，必须将卡片拖到两席中间才开始碰撞 |
| 碰撞轮数 | 默认一轮“质疑—回应”，继续碰撞后置 |
| 碰撞候选 | 正常提供 2—3 个；候选不足时允许降级为 1 个预置或可验证候选 |
| AI 角色 | 检索、生成、校验和结构化归纳分开 |
| 搜索方式 | Agent 使用指定 Skill 搜索允许范围内的资料；本地语料作为备选，不要求向量库成为核心依赖 |
| 最终产物 | “讨论地图 + 灵魂金句”是一张合并的可分享卡片 |
| 用户表达 | 可选；用户不确定、拒绝全部候选或提前结束都属于有效结果 |

## 4. 角色与边界

### 4.1 角色表

| 角色 | 稳定 ID | 出现时机 | 职责 | 不做什么 |
|---|---|---|---|---|
| 第一席·行动派 | action | 第一席阶段 | 关注健康、不可逆损失和及时止损，同时说明行动边界 | 不冒充真实答主，不把冲动辞职说成唯一答案 |
| 第二席·现实派 | realist | 第二席阶段 | 关注现金流、家庭责任、替代方案和风险承受能力 | 不把风险控制简化为无限期忍耐 |
| 第三席·条件视角 | conditional | 用户确认隐藏分歧后，可选 | 重构问题，提供新的判断框架和工具 | 不重复前两席，不做简单折中 |
| 用户 | — | 全程 | 选择、追问、发起碰撞、校准和表达 | 不被强迫得出最终结论 |
| 主持人 | director | 全程 | 欢迎、串场、提示阶段、复述已发生内容 | 不替用户判断，不捏造用户心理 |
| 知识系统 | — | 服务端 | 搜索、检索、生成、来源标注和校验 | 不把无关材料伪装成证据 |

用户不是“第四席”，而是这张桌子的发起者和判断参与者。

### 4.2 主持人规则

主持人可以：

- 告知当前处于哪个阶段；
- 说明下一步可做什么；
- 复述已经发生的质疑和回应；
- 帮助用户理解隐藏分歧；
- 生成结果页的结构化说明。

主持人不得：

- 推测用户没有明确表达的情绪；
- 代替用户说“你已经决定了”；
- 把某一席说成客观正确；
- 编造讨论中没有出现的事实。

## 5. 完整用户流程

    进入话题
      ↓
    第一席发言
      ├─ 可选：举手追问第一席 → 回到第一席锚点
      ↓
    第二席发言
      ├─ 可选：举手追问第二席 → 回到第二席锚点
      ↓
    记录首次倾向（三选一）
      ↓
    选择 2—3 个碰撞候选中的一个
      ├─ 或输入自己的碰撞问题
      ↓
    进入 collision-drag
      ↓
    将碰撞点卡片拖到两席中间
      ↓
    另一席质疑 → 原席回应
      ↓
    生成 2—3 个隐藏分歧候选
      ↓
    用户确认、修改、拒绝或直接整理
      ↓
    可选：生成第三席预览
      ├─ 邀请第三席入桌
      ├─ 换一个第三视角
      └─ 不邀请，直接整理
      ↓
    用户表达离桌时理解（可跳过）
      ↓
    生成讨论地图 + 灵魂金句分享卡

### 5.1 必走主流程

    听第一席
    → 听第二席
    → 选择倾向
    → 选择碰撞点
    → 拖动碰撞点
    → 完成一轮质疑—回应
    → 处理隐藏分歧
    → 生成结果卡

### 5.2 可选支线

- 举手追问第一席或第二席；
- 补充一次个人条件；
- 自己输入碰撞问题；
- 继续一轮碰撞；
- 生成第三席预览；
- 邀请第三席入桌；
- 换一个第三视角；
- 查看原文来源；
- 提前结束圆桌。

可选支线不得阻塞最短路径，也不得改变主进度的含义。

## 6. 阶段说明

### 6.1 阶段 A：进入话题

页面展示：

- 话题标题；
- 一句话冲突描述；
- 来源数量；
- 预计体验时长；
- “加入拼桌”按钮。

Demo 首版至少支持“年轻人该不该裸辞？”。如果支持多个话题，任何话题都必须有独立来源和碰撞配置，不得把默认话题文案套到所有话题。

### 6.2 阶段 B：第一席发言

第一席必须展示：

- 1—2 句面向当前问题的完整判断；
- 主要理由；
- 适用边界；
- 2—3 个可碰撞的具体论点；
- 当前席位名称和稳定 ID；
- 来源类型和原文入口；
- “举手追问这席”入口。

合格观点：

> 如果工作已经持续影响睡眠和身体状态，继续留下也在产生健康成本。离开可能是停止损失，但前提是先看清必须保护的东西。

不合格观点：

> 健康很重要。

### 6.3 阶段 C：第二席发言

第二席展示结构与第一席一致，但必须体现真实差异。

合格观点：

> 如果现金储备有限，裸辞可能把工作焦虑转化成生活压力。求职周期不可完全预测，行动前需要先确认替代方案和最低安全线。

第二席不能只是把第一席改写成“反对”。

### 6.4 阶段 D：单席追问

用户可在第一席或第二席发言后举手追问。

追问要求：

1. 当前席位必须明确；
2. 用户最新问题必须单独传入 Agent；
3. 必须结合当前席位立场回答；
4. 必须回应新增情境；
5. 必须说明原判断是否需要调整；
6. 必须提供边界、触发条件或不确定性；
7. 只能使用当前话题和当前席位允许的来源；
8. 来源不足时必须明确说明；
9. 结束后回到原席位锚点；
10. 追问不算新一轮碰撞，也不提前生成第三席。

禁止：

    用户问“如果孩子生病了呢”
    → 直接返回一段“裸辞半年很快乐”的原文

### 6.5 阶段 E：记录首次倾向

两席完成后，询问：

> 听完两个观点，现在的你更接近哪一种判断？

首版只提供三个选项：

- 更接近第一席；
- 更接近第二席；
- 暂时无法判断。

“两边都有道理”“两边都没说到重点”可通过离桌自由表达记录，不放入首版必选项。

首次倾向只代表这一时刻的用户选择，不代表系统推测用户原本的心理。

### 6.6 阶段 F：选择碰撞点

碰撞点必须是可被检验的具体判断。

合格示例：

- 三个月存款够不够支撑裸辞？
- 继续留下本身是不是一种风险？
- 哪种损失更难恢复？
- 家庭责任是否改变行动时机？

不合格示例：

- 健康问题；
- 经济问题；
- 裸辞风险。

正常情况下系统提供 2—3 个候选。候选可以来自：

- 预置的合格碰撞点；
- 基于两席已发生内容的 Agent 建议；
- 用户追问和补充条件中已经出现的具体问题。

首版不承诺必须由 AI 从零发现碰撞点。若动态候选不稳定，至少提供 1 个预置或可验证候选，流程不能被候选生成失败阻塞。

用户也可以输入自己的问题。

### 6.7 阶段 G：碰撞点拖动

选择碰撞点后，进入独立的 collision-drag 状态。

交互含义：

    点击碰撞点 = 决定“碰什么”
    拖动碰撞点卡片 = 决定“现在开始碰”

规则：

- 仅点击不会触发质疑—回应；
- 用户可以重新选择碰撞点；
- 必须将卡片拖到第一席和第二席之间的桌面中央；
- 拖动成功后卡片固定在两席之间；
- 页面显示“正在围绕这句话碰撞”；
- 拖动只负责触发碰撞，不直接生成第三席；
- 未完成拖动时不得调用碰撞接口；
- 未完成碰撞时不得调用第三席接口。

### 6.8 阶段 H：一轮质疑—回应

固定顺序：

1. 用户选中哪一席的判断；
2. 另一席先提出质疑；
3. 原席位针对质疑回应；
4. 主持人指出双方可能真正不同的地方。

质疑规则：

- 必须指向原席已表达过的具体内容；
- 不得虚构或夸张原席立场；
- 新出现的外部事实必须有来源；
- 不能只复述整篇来源；
- 默认只完成一轮。

回应规则：

- 必须读取对方完整质疑；
- 必须直接回答质疑；
- 可以保留原立场，但要补充边界；
- 不得突然切换到另一席身份；
- 不得把检索结果直接当成回应。

### 6.9 阶段 I：确认隐藏分歧

系统根据真实碰撞输出 2—3 个候选，候选必须绑定对话证据。

候选可以揭示：

- 风险判断差异；
- 行动时机差异；
- 缓冲方案是否可行；
- 损失是否可逆；
- 双方默认前提差异；
- 用户新增条件改变了哪一笔账。

用户可以选择、组合、修改、选择“都不是”或直接整理结果。

用户拒绝全部候选时，不得强迫确认，也不得伪造一个用户没有认可的分歧。

### 6.10 阶段 J：第三席可选增强

第三席只能在以下条件全部满足后生成：

1. 碰撞点已拖动确认；
2. 质疑和回应均已完成；
3. 隐藏分歧候选已经生成；
4. 用户确认或修正了一个隐藏分歧。

第三席必须：

- 来源于本桌真实碰撞和用户确认的隐藏分歧；
- 解释前两席为什么争不拢；
- 提供新的问题重构；
- 提供可执行判断工具；
- 不重复前两席；
- 不只是简单折中；
- 明确自己的证据边界。

用户可选择邀请第三席、换一个第三视角或不邀请直接整理。

第三席生成失败、来源不足或用户不邀请时，都必须正常进入结果页。

## 7. 最终产物：讨论地图 + 灵魂金句分享卡

### 7.1 产品定义

讨论地图和灵魂金句是同一个最终产物，不是两个独立页面。

讨论地图负责展示这桌讨论留下的结构；灵魂金句负责压缩用户真正带走的判断。

最终卡片可在页面查看、截图分享、导出为图片和复制分享内容。

### 7.2 卡片固定结构

    ┌─────────────────────────┐
    │       讨论余波           │
    │                         │
    │   外围发现 A   外围发现 B │
    │                         │
    │        中心问题          │
    │                         │
    │   外围发现 C             │
    │    用户立场轨迹          │
    │─────────────────────────│
    │        带走一句          │
    │                         │
    │       灵魂金句           │
    │                         │
    │    分享 · 提供反馈       │
    └─────────────────────────┘

### 7.3 讨论地图规范

必须固定：

- 中心问题：1 个；
- 外围发现：最多 3 个；
- 用户轨迹：1 条；
- 地图区域不放长段落；
- 外围节点每个 4—6 字；
- 中心问题建议 8—16 字，最多两行；
- 轨迹只表达“起点 → 碰撞 → 当前”；
- 颜色不能单独承担语义，必须有文字标签。

外围发现建议分别代表：

1. 核心冲突；
2. 隐藏前提；
3. 第三席实际产生的新视角，或未邀请第三席时的未解问题。

如果第三席没有正式入桌：

- 不得把第三席候选视角写成既成结论；
- 第三个外围发现只能来自前两席碰撞、已确认隐藏分歧、未解问题或用户轨迹；
- 不得标记为第三席观点。

### 7.4 用户立场轨迹

轨迹只显示：

    起点 → 碰撞 → 当前

允许的终点：

- 第一席；
- 第二席；
- 第三席（仅在正式邀请并实际发言后）；
- 暂时无法判断。

轨迹不写长解释。详情可通过点击节点或查看卡片下方说明展开。

### 7.5 灵魂金句规范

每桌生成 1 句灵魂金句。

生成输入只能来自已经发生的内容：

- 中心问题；
- 用户首次倾向；
- 用户选择的碰撞点；
- 质疑与回应；
- 用户确认的隐藏分歧；
- 第三席实际发言（如有）；
- 用户离桌表达（如有）。

规则：

- 建议 18—32 字，最多 40 字；
- 不直接复述中心问题；
- 不使用“AI 认为”“本次讨论表明”等系统口吻；
- 不强行给出“应该辞职 / 不应该辞职”的结论；
- 表达新的判断框架、保护边界或下一步观察线；
- 不得直接复制某条知乎原文；
- 第三席未入桌时不得引用第三席候选视角作为既成事实；
- 用户没有明确表达时，不能伪装成用户口吻。

示例：

> 你不是在选辞不辞，而是在选哪种代价更能承受。

### 7.6 分享与来源

卡片保留：

- 分享；
- 提供反馈；
- 查看本桌参考来源。

来源放在地图主体之外的折叠区，展开后显示第一席、第二席、碰撞和第三席 claim 对应的来源。

分享卡不放：

- 完整聊天记录；
- 用户私密补充；
- Access Secret；
- API Key；
- 未授权肖像；
- 未经核验的原文全文。

## 8. Agent、Skill 与知识来源规则

### 8.1 总体原则

每次需要回答的环节都遵循：

    识别用户新增情境
      ↓
    限定 topicId + seatId + 当前任务
      ↓
    使用指定 Skill 搜索允许范围内的资料
      ↓
    读取本桌上下文
      ↓
    调用当前 Agent 生成新回答
      ↓
    校验席位、来源和问题相关性
      ↓
    返回 reply + 来源

Skill 是搜索和行为规范，不是上下文的替代品。每次请求都必须显式传入当前席位和用户最新问题。

### 8.2 来源优先级

1. 当前话题、当前席位下的实时或可验证知乎资料；
2. 项目本地备选语料；
3. 基于本桌对话的 AI 综合，必须标记证据不足。

本地语料或 Skill 搜索结果只能作为证据，不是最终回答。禁止把检索结果原文前若干字符直接当作追问、碰撞或第三席回答。

### 8.3 内容类型标注

系统必须区分：

- 知乎来源；
- Agent 综合；
- 本桌归纳；
- 用户表达；
- 预览，未正式入桌；
- 材料不足。

### 8.4 AI 综合视角兜底

当知乎资料无法充分支持第三席的某个 claim 时：

1. 优先重新搜索符合该 claim 的资料；
2. 仍不足时尝试更换第三视角框架；
3. 本桌碰撞证据足够时，允许生成 AI 综合视角；
4. 标记 origin=ai_synthesis；
5. 标记 sourceStatus=insufficient；
6. 返回 sourceNotice；
7. 不显示知乎作者署名为第三席背书；
8. 涉及医疗、法律、债务或重大财务风险时，只给“材料不足”和一般判断工具。

硬性规则：

- Skill 搜索结果必须带来源身份和 URL；
- 生成结果必须记录使用了哪些证据；
- 检索失败不能静默复用上一问回答。

## 10. 检索、生成与校验

### 10.1 三层职责

| 层 | 职责 |
|---|---|
| 检索层 | 按话题、席位和任务找相关资料 |
| 生成层 | 根据用户问题、席位立场和资料生成新回答 |
| 校验层 | 检查席位、来源、问题相关性、长度和风险边界 |

### 10.2 模式枚举

    generated   检索证据后由聊天模型生成
    retrieval   仅返回来源摘录，必须显式标注
    fallback    无 API、超时或生成失败时的规则兜底

不得把 retrieval 或 fallback 伪装成 generated。

### 10.3 席位一致性不变量

任一追问或碰撞结果必须同时满足：

> 回答席位正确、来源席位正确、回答问题正确。

请求至少包含：

    topicId
    seatId
    sessionId
    requestId
    question

响应至少包含：

    topicId
    seatId
    requestId
    reply
    sourceIds[]
    sourceSeatIds[]
    mode

### 10.4 并发请求规则

- 每次请求生成唯一 requestId；
- 前端只接受当前最新请求的响应；
- 旧请求不得覆盖新结果；
- 切换席位时清空旧回答；
- 发生校验失败时返回当前席位安全兜底；
- 不得返回另一席内容凑数。

## 11. 证据分层与第三席 Schema

### 11.1 证据类型

| 证据类型 | 用途 |
|---|---|
| 外部知识证据 | 支撑事实、研究结论和经验材料 |
| 席位立场证据 | 支撑行动派或现实派的具体判断 |
| 本桌对话证据 | 支撑碰撞点、隐藏分歧、地图和金句 |
| 用户表达证据 | 支撑首次倾向与离桌理解 |
| generationEvidence | 解释第三席为什么由本桌生成 |
| knowledgeEvidence | 支撑第三席中的具体 claim |

### 11.2 第三席证据结构

    {
      "generationEvidence": {
        "divergenceId": "irreversible-loss",
        "conversationQuoteIds": ["quote_1", "quote_2"]
      },
      "knowledgeEvidence": {
        "claims": [
          {
            "claim": "……",
            "importance": "key",
            "sourceIds": ["source_1"],
            "supportStatus": "supported",
            "supportExplanation": "该来源具体支持……"
          }
        ]
      }
    }

规则：

- generationEvidence 回答“为什么第三席出现”；
- knowledgeEvidence 回答“哪条来源支持哪句 claim”；
- 每条来源必须能指向具体 claim；
- 不能用关键词命中代替语义相关性；
- 关键 claim 缺少充分依据时，整体 sourceStatus 必须是 insufficient；
- insufficient 时允许用户换视角或跳过；
- 不要求一篇来源完整对应整个第三席。

## 13. 状态机

    home
      → intro
      → first-seat
      → second-seat
      → tendency
      → collision-point
      → collision-drag
      → collision-response
      → divergence
      → result

    perspective-preview、third-seat 为可选增强状态。
    followup 是覆盖在 first-seat / second-seat 上的临时子状态，结束后回到原状态。

### 13.1 状态进入和退出条件

| 状态 | 进入条件 | 退出条件 |
|---|---|---|
| home | 用户尚未开始 | 点击进入话题 |
| intro | 话题已加载 | 点击开始 |
| first-seat | 第一席来源和观点就绪 | 第一席展示完成 |
| second-seat | 第一席完成 | 第二席展示完成 |
| tendency | 两席均完成 | 用户选择三选一 |
| collision-point | 首次倾向已记录 | 用户选择或输入碰撞点 |
| collision-drag | 已选择碰撞点 | 卡片拖到两席中间 |
| collision-response | 拖动成功 | 质疑和回应均完成 |
| divergence | 碰撞内容完整 | 用户确认、修改、拒绝或直接整理 |
| perspective-preview | 用户确认隐藏分歧 | 邀请、换视角或跳过 |
| third-seat | 用户明确邀请 | 第三席发言完成 |
| result | 已有足够讨论记录 | 重置或离开 |

### 13.2 会话状态

    type SessionState = {
      sessionId: string;
      topicId: string;
      stage: Stage;
      firstSeatStatement?: SeatStatement;
      secondSeatStatement?: SeatStatement;
      followups: FollowupRecord[];
      tendency?: "closer_first" | "closer_second" | "undecided";
      selectedCollisionPoint?: CollisionPoint;
      collision?: CollisionRecord;
      divergences: DivergenceCandidate[];
      confirmedDivergence?: string;
      perspective?: PerspectivePreview;
      thirdSeatInvited: boolean;

      discussionMap?: DiscussionMap;
      soulSentence?: string;
      updatedAt: string;
    };

## 14. 失败与降级路径

| 情况 | 处理 |
|---|---|
| 第一席来源不足 | 使用当前席位明确标注的本地备选或安全兜底 |
| 第二席来源不足 | 使用当前席位明确标注的本地备选或安全兜底 |
| 追问 API 超时 | 返回当前席位安全兜底，并提供重试 |
| 追问无相关来源 | 明确显示“当前材料不足”，不得复用上一问 |
| 碰撞候选不足 | 至少提供一个预置或可验证候选 |
| 碰撞生成失败 | 提供重试或基于已发生内容直接整理 |
| 隐藏分歧候选不足 | 允许用户自由输入或直接整理 |
| 用户拒绝全部隐藏分歧 | 生成简版结果 |
| 第三席来源不足 | 标记 sourceStatus=insufficient，允许换视角或跳过 |
| 第三席生成失败 | 直接进入结果页，不虚构第三席发言 |
| 用户不邀请第三席 | 基于前两席、碰撞和隐藏分歧生成结果 |
| 用户提前结束 | 只总结已经发生的内容 |
| 并发响应过期 | 丢弃旧响应 |
| 涉及医疗、法律、债务或危机 | 提供一般信息和求助建议，不做确定性决策 |

## 15. 结果卡片规则

### 15.1 有第三席入桌

卡片可使用：

- 前两席碰撞；
- 用户确认的隐藏分歧；
- 第三席实际发言；
- 用户轨迹；
- 用户离桌表达。

不得把第三席预览中未实际发言的内容写入卡片。

### 15.2 不邀请第三席

卡片只能使用：

- 前两席观点；
- 已完成的质疑—回应；
- 用户确认的隐藏分歧；
- 未解决问题；
- 用户轨迹；
- 用户离桌表达。

第三个外围节点可以叫：

- 尚未解决；
- 仍需确认；
- 选择边界；
- 下一步验证。

但不能写成第三席已经提供的新观点。

### 15.3 卡片分享

分享操作默认输出：

- 中心问题；
- 三个外围短结论；
- 立场轨迹；
- 灵魂金句；
- 来源数量和来源入口；
- 知识拼桌标识。

不输出私密用户条件、完整会话记录、未授权内容、API 凭据或未经用户确认的心理判断。

## 17. 验收标准

### 17.1 产品流程

1. 第一席和第二席以独立阶段依次出现；
2. 用户可追问任一席，结束后回到对应锚点；
3. 首次倾向只有三个选项；
4. 用户可选择或输入具体碰撞点；
5. 仅点击碰撞点不会触发碰撞；
6. 卡片拖到两席中间后才触发质疑—回应；
7. 拖动不会直接生成第三席；
8. 另一席先质疑，原席位再回应；
9. 用户可确认、修改、拒绝隐藏分歧；
10. 第三席只有在前置条件满足后才生成；
11. 第三席可以跳过；
12. 不邀请第三席仍可完成结果页；
13. 用户离桌表达可以跳过；
14. 任一步失败都能基于已发生内容整理结果。

### 17.2 回答质量

15. 用户问“如果孩子生病了呢”时，回答必须处理孩子照护、家庭责任或相关新增条件；
16. 每个回答都知道当前话题、当前席位和最新问题；
17. 追问和碰撞回答不能直接等于某条来源的原文截取；
18. 每次新问题都触发新的搜索或明确的安全降级；
19. 来源不足时不得拼接无关内容；
20. 质疑必须指向真实发生的具体观点；
21. 回应必须读取并回应完整质疑；
22. 隐藏分歧必须能回溯到本桌对话证据。

### 17.3 席位与并发安全

23. action 请求只能返回 action 来源；
24. realist 请求只能返回 realist 来源；
25. 页面席位、请求 seatId、响应 seatId 三者一致；
26. 并发追问时旧请求不能覆盖新请求；
27. 第三席未正式邀请时，不得写成已参与讨论；
28. 用户未表达的心理变化不得写入结果。

### 17.4 结果卡片

29. 中心问题只有一个；
30. 外围节点最多三个；
31. 每个外围节点 4—6 字；
32. 轨迹只表达起点、碰撞和当前；
33. 灵魂金句最多 40 字；
34. 地图和金句在同一张可分享卡片中；
35. 第三席未入桌时，卡片不出现第三席既成观点；
36. 来源、Agent 综合、本桌归纳和用户表达有明确区分。

### 17.5 第三席证据

37. generationEvidence 指向真实碰撞、隐藏分歧和用户确认；
38. 每个关键 claim 有 sourceIds 和 supportStatus；
39. 每条来源能够说明支撑哪条 claim；
40. 关键词命中不能代替语义相关性；
41. 关键 claim 不足时返回 sourceStatus=insufficient；
42. 来源不足时不伪装成知乎观点；
43. 用户可以换视角或跳过第三席。

## 18. 回归测试脚本

使用话题“年轻人该不该裸辞”，依次验证：

1. 进入后先看到第一席，再看到第二席；

6. 快速发起两次追问，最终只显示最后一次结果；
7. 完成三选一倾向记录；
8. 选择 2—3 个碰撞候选中的一个；
9. 仅点击碰撞点，确认不会触发碰撞；
10. 将卡片拖到两席中间，确认才开始质疑—回应；
11. 确认拖动不会直接调用第三席接口；
12. 完成一轮质疑—回应；
13. 拒绝全部隐藏分歧，确认仍能进入结果；
14. 在隐藏分歧未确认前，确认第三席接口不可调用；
15. 不邀请第三席，确认结果卡不写第三席已发言；

- 检索来源 ID 和来源席位；
- generated / retrieval / fallback；
- 模型或 Skill 搜索耗时；
- 校验是否通过；
- 是否发生降级。

不得记录 API Key、Access Secret、用户不必要的敏感信息或私密补充内容的完整原文。

### 19.2 质量指标

- 第一席完成率；
- 第二席完成率；
- 碰撞点选择率；
- 碰撞完成率；
- 隐藏分歧确认率；
- 第三席邀请率；
- 结果卡生成率；
- 结果卡分享率；

## 21. 对外表达

### 30 秒介绍

> 知识拼桌先让你听两个来自知乎真实内容的不同观点。你可以分别追问，也可以挑一句真正有分歧的话，把它递到两席之间，让它们完成一次质疑和回应。AI 再帮你看见双方没有说清楚的隐藏分歧，第三席可以邀请，也可以跳过。最后你会带走一张讨论地图和一句灵魂金句，而不是一个替你做决定的答案。

### 最短版本

> 听两个真实观点，挑一句让它们碰撞，看见隐藏分歧，第三席可请可不请，最后带走一张讨论地图和一句灵魂金句。

### 核心产品逻辑

> 每次回答都必须知道当前话题、当前席位、用户最新问题和本桌上下文。检索结果只能作为证据，不能直接替代回答。第三席是可选增强，讨论地图和灵魂金句是最终合并产物，用户始终拥有对自己理解的解释权。
